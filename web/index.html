Hello. My project is a delivery drone that has to decide whether it is safe to fly, and how. It combines three algorithms from the course: Bayesian inference, a Markov decision process and A* search.

    


    

      
01 · Problem & objectives

      
Wind breaks drones.
Sensors are noisy.

      

        

          
the situation

          
    
            
  • a drone carries one parcel across a 6×6 map
    • 
            
  • strong wind over the open field can crash it
    • 
            
  • one sensor reading before take-off · misses 20% of storms, false-alarms 20% of calm days
    • 
          

        

        

          
three questions → three algorithms

          
How likely is strong wind?Bayesian inference

          
Fly now or wait?Markov decision process

          
Which route?A* search

        

      

      
objectivemake all three decisions automatically from one reading, show every step, prove it with tests

      
Operators of small drones must decide before every flight. The sensor is noisy, waiting costs time, and the shortest route crosses open terrain. I split this into three questions and solve each with a different course topic. All numbers are toy values, clearly labelled.

    


    

      
02 · System design

      
One belief, two consumers

      
      

        
Bayes → MDPposterior = belief over the hidden weather

        
Bayes → A*posterior scales the cost of open-field cells

        
MDP → A*route is flown only if the MDP says fly

      

      
This is the key point: the algorithms are connected, not three separate demos. Bayes produces one number, the probability of strong wind. The MDP uses it as its belief to choose fly or wait, and A* uses it to make open-field cells more expensive.

    


    

      
03 · Topic 1 — Probabilistic reasoning

      
Bayesian inference

      
P(strong | e) = P(e | strong) · P(strong) / P(e)

      

        

          
worked example · scenario C

          

            
prior P(strong)0.30

            
readingalert

            
P(alert,strong) = 0.8 × 0.30.24

            
P(alert,calm) = 0.2 × 0.70.14

            
P(alert) = 0.24 + 0.140.38

            
P(strong | alert) = 0.24 / 0.380.632

          

        

        

          
30%
→
63.2%

          
one alert more than doubles the belief · a quiet reading drops it to 9.7%

        

      

      
The wind state is hidden; we only see the sensor. Prior 0.3. The alert has likelihood 0.8 if windy and 0.2 if calm. Multiply, add to get the evidence 0.38, divide: 0.632. If the sensor were 50/50, the posterior would equal the prior.

    


    

      
04 · Topic 2 — Sequential decisions

      
Markov decision process

      

        

          

            
flywait

            
calm+10−2

            
windy−20−1

          

          
rewards R(s,a) · fly ends the mission · waiting lets the weather change (calm stays 80%, windy stays 60%) · γ = 0.9

          
Q(s,a) = R(s,a) + γ Σ P(s′|s) V(s′)

        

        

          
value iteration → decision under belief b

          

            
V(calm)10.00

            
V(windy) = 2.6 / 0.465.65

            
Q_b(fly) = 10 − 30b−8.95

            
Q_b(wait) ≈ 6.22 − 0.57b5.86

            
fly only if b < 12.9% · b = 63.2%WAIT

          

        

      

      
States calm and windy, actions fly and wait. Value iteration repeats the Bellman update until it converges, 27 updates. We do not know the state, so I weight the Q values by the Bayesian belief — the QMDP approximation. Setting the two lines equal gives the 12.9 percent threshold.

    


    

      
05 · Topic 3 — Search

      
A* search

      

        

          
f(n) = g(n) + h(n)

          
    
            
  • h = Manhattan distance · admissible, every step costs ≥ 1
    • 
            
  • normal cell costs 1 · open-field cell costs 1 + 25·P(wind)
    • 
            
  • shortcut: 11 moves through 2 field cells · detour: 15 moves
    • 
            
  • A* takes the shortcut only while P(wind) < 8%
    • 
          

        

        

          
A · P = 2.7% · shortcut

          
B · P = 9.7% · detour

        

      

      
A* expands the node with the smallest f = g + h. Manhattan never overestimates because each move costs at least one, so the route is optimal — it matches BFS when there is no wind. The wind belief changes the cost of the open field, so the same algorithm picks a different route.
